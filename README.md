# speed_test

Консольный замер скорости скачивания с вашего компьютера. Скрипт несколько раз
подряд скачивает один и тот же файл по указанному адресу и показывает, сколько
занял каждый запрос, перцентили времени и итоговую скорость канала.

Только стандартная библиотека Python, никаких зависимостей.

## Требования

- Python 3.9 или новее

## Быстрый старт

```bash
python speedtest.py https://proof.ovh.net/files/100Mb.dat -n 3
```

## Как это работает

1. **Запросы.** Скрипт делает `N` запросов к URL строго последовательно: каждый
   следующий начинается только после того, как предыдущий скачан целиком.
   Параллельных соединений нет, поэтому замер показывает скорость одного потока.
2. **Замер времени.** Время считается от отправки запроса до получения последнего
   байта тела ответа, по таймеру `time.perf_counter()`. Тело читается полностью и
   никуда не сохраняется, на диск ничего не пишется.
3. **Проверка ответа.** Если сервер вернул ошибку (403, 404, недоступный хост,
   проблема с сертификатом) или вместо файла прислал HTML-страницу, скрипт
   останавливается с понятным сообщением, а не считает скорость по мусору.
4. **Статистика.** По завершении всех запросов считаются:
   - **avg**: среднее время одного запроса;
   - **p50 / p90 / p99**: перцентили времени. p90 означает, что 90% запросов
     уложились в это время. Перцентили интерполируются строго внутри диапазона
     реальных замеров;
   - **Скачано**: общий объём за все запросы;
   - **Скорость**: общий объём, делённый на общее время. Так один медленный
     запрос влияет на результат пропорционально своей длительности, а не
     искажает среднее из скоростей.

Единицы десятичные, как в тарифах провайдеров: 1 MB = 1 000 000 байт.
Скорость выводится в мегабайтах в секунду и, в скобках, в мегабитах
(1 MB/s = 8 Mbit/s).

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `url` | обязательный | Адрес файла для скачивания |
| `-n N` | `10` | Число запросов, минимум 2 (иначе перцентили не посчитать) |
| `-v`, `--verbose` | выключен | Подробные логи: статус и заголовки ответа, редиректы |
| `-h`, `--help` | | Справка |

## Примеры запуска

> Цифры в примерах ниже иллюстративные: у вас они будут зависеть от канала и сервера.

### Обычный замер

```bash
python speedtest.py https://proof.ovh.net/files/100Mb.dat -n 3
```

```
22:15:01 INFO  Старт замера: https://proof.ovh.net/files/100Mb.dat, запросов: 3
22:15:01 INFO  Запрос 1/3: скачивание...
#1    104.86 MB    8.62 s  12.16 MB/s (97.3 Mbit/s)
22:15:10 INFO  Запрос 2/3: скачивание...
#2    104.86 MB    8.41 s  12.47 MB/s (99.7 Mbit/s)
22:15:18 INFO  Запрос 3/3: скачивание...
#3    104.86 MB    8.55 s  12.26 MB/s (98.1 Mbit/s)
22:15:27 INFO  Замер завершён за 25.58 s

Время:    avg 8.53 s | p50 8.55 s | p90 8.61 s | p99 8.62 s
Скачано:  314.57 MB
Скорость: 12.30 MB/s (98.4 Mbit/s)
```

Строки с `INFO` показывают ход работы, строки `#1`, `#2`… содержат результат
каждого запроса, а блок в конце даёт сводку.

### Подробный режим

```bash
python speedtest.py https://proof.ovh.net/files/100Mb.dat -n 2 -v
```

```
22:16:40 INFO  Старт замера: https://proof.ovh.net/files/100Mb.dat, запросов: 2
22:16:40 INFO  Запрос 1/2: скачивание...
22:16:40 DEBUG Ответ: HTTP 200, application/octet-stream, Content-Length: 104857600
#1    104.86 MB    8.48 s  12.37 MB/s (98.9 Mbit/s)
...
```

Полезно, когда результат выглядит странно: видно, что реально отдаёт сервер и
не было ли редиректа.

### Сохранить результат в файл

Логи пишутся в stderr, результаты в stdout, поэтому их можно разделить:

```bash
python speedtest.py https://proof.ovh.net/files/100Mb.dat -n 5 > result.txt
```

В консоли останется ход работы, в `result.txt` попадут только строки замеров и
сводка.

### Точная оценка p99

На 10 запросах p99 практически совпадает с самым медленным запросом. Чтобы
перцентиль был осмысленным, нужна выборка побольше, а файл лучше взять поменьше:

```bash
python speedtest.py https://proof.ovh.net/files/10Mb.dat -n 100
```

## Ошибки

Ошибки выводятся одной строкой, скрипт завершается с кодом `1`:

```
22:18:02 ERROR Ошибка запроса к https://example.com/nope.bin: HTTP Error 404: Not Found
```

```
22:18:30 ERROR Ошибка запроса к http://example.com/file: вместо файла пришла HTML-страница (3012 байт) с http://example.com/file
```

Прерывание по Ctrl+C завершает скрипт с кодом `130` без трейсбека:

```
22:19:11 WARNING Прервано пользователем после 4 запросов
```

| Сообщение | Причина и что делать |
|---|---|
| `HTTP Error 403: Forbidden` | Сервер блокирует запрос. Попробуйте другой адрес |
| `No address associated with hostname` | Домена не существует или нет интернета |
| `CERTIFICATE_VERIFY_FAILED` | Сертификат сервера не подходит. Попробуйте `http://` или другой сервер |
| `вместо файла пришла HTML-страница` | По адресу лежит не файл. Проверьте URL с флагом `-v` |

## Советы по точности

- Берите файл от 10 МБ. На маленьких файлах результат определяется задержкой
  соединения, а не шириной канала.
- Выбирайте сервер поближе географически: скорость до далёкого сервера
  упирается в маршрут, а не в ваш тариф.
- Помните про объём трафика: 10 запросов по 100 МБ это около 1 ГБ.
- Скрипт меряет один поток. Онлайн-спидтесты обычно открывают несколько
  соединений сразу, поэтому могут показывать больше.

## Структура кода

Код разделён на независимые слои, в файле они отделены заголовками-комментариями:

| Слой | Что внутри | Ответственность |
|---|---|---|
| Модели | `Sample`, `Report` | Результат одного запроса и сводная статистика |
| Измерение | `http_fetch`, `measure` | Единственное место с сетевым вводом-выводом |
| Статистика | `summarize` | Чистые вычисления без I/O |
| Форматирование | `fmt_*`, `format_sample`, `format_report` | Как числа выглядят в консоли |
| Точка входа | `parse_args`, `setup_logging`, `main` | Связывает части между собой |

`measure` принимает функцию скачивания параметром, поэтому её легко подменить,
например заглушкой в тестах или реализацией на `requests`, не трогая остальной код.
